## 一、快速跑通

**所有命令必须在仓库根目录执行。**

```bash
# 1. 装依赖（Python 3.13 + 虚拟环境）
pip install -r requirements.txt
pip install -r requirements-dev.txt     # 需要跑测试时

# 2. 配 Key：复制模板后填入自己的智谱 Key
cp .env.example .env
#    编辑 .env → ZHIPU_API_KEY=你的key
#    申请：https://open.bigmodel.cn/usercenter/apikeys
#    （.env 已被 .gitignore 排除，不会误提交）

# 3. 生成演示文档（可跳过，data/ 已自带 3 个）
python generate_samples.py

# 4. 入库（第一次会调 Embedding API，几十秒）
python knowledge_base.py

# 5. 启动界面
./.venv/Scripts/streamlit.exe run rag_app.py      # 服装电商（纯 RAG）
./.venv/Scripts/streamlit.exe run agent_app.py    # 智扫通（Agent）

# 6. 跑测试（纯单元，不调 API）
pytest -q
```

> ⚠️ **Streamlit 必须用 `streamlit run` 启动。** 用 `python rag_app.py` 会进入 bare mode，
> 打印 `missing ScriptRunContext` 且**不会启动任何 Web 服务**。
> 同时开两个 app 时给第二个加 `--server.port 8502`。

预期入库输出：

```
✅ 扫地机器人用户手册.pdf: 1 块
✅ 服装售后FAQ.docx: 1 块
✅ 综合知识.txt: 1 块

🎉 新处理 3 个文件，跳过 0 个，共 3 块
```

三份文档都短于 `CHUNK_SIZE=500`，所以各切 1 块、合计 3 块。
再次运行会全部显示「⏭ 未变化」——指纹没变，增量入库生效了。

## 二、新人常见疑问

**Q：为什么 `ZhipuEmbeddings` 要自己写？LangChain 没有智谱的 Embedding 吗？**
有，但需要额外依赖且版本兼容性差。实现 `Embeddings` 抽象类只要两个方法（`embed_documents` / `embed_query`），二十行代码，可控性最高。`batch_size=64` 是智谱单次请求的条数上限。

**Q：为什么入库分批 200，Embedding 内部又分批 64？**
两个层次。200 控制内存和单次写库事务大小；64 是 API 硬限制。LangChain 会自动把 200 条再切给 64 一批。

**Q：`collection_metadata={"hnsw:space": "cosine"}` 为什么一定要设？**
Chroma 默认 L2 欧氏距离。文本 Embedding 关心的是**方向**而非长度，余弦距离对归一化不敏感，中文语义检索更稳。**建库与查询必须一致。**

**Q：改了 `data/` 里的文档，为什么答案没变？**
忘了重跑 `python knowledge_base.py`。**入库不是自动的**——这是最高频问题。

**Q：改了 `.env` 里的 Key 不生效？**
系统环境变量存在时优先于 `.env`（`load_dotenv` 默认 `override=False`）。改 Key 前先确认 `echo $ZHIPU_API_KEY`。

**Q：所有问题都答「知识库中暂未找到相关信息」？**
多半没在仓库根目录启动，`./chroma_db` 是相对 CWD 的路径，指向了别处的空库。

**Q：`test.py` 是干嘛的？**
Python 基础语法练习草稿，与项目无关，已被 `.gitignore` 排除。

## 三、动手练习（推荐按顺序做）

| # | 练习 | 涉及文件 | 学到什么 |
|---|---|---|---|
| 1 | 往 `data/` 加一个 `.md` 文件，跑入库，验证能检索到 | `data/`, `knowledge_base.py` | 完整离线链路 |
| 2 | 改 `CHUNK_SIZE` 为 200，`force_rebuild=True` 重建，对比答案质量 | `config.py` | 切块粒度对检索的影响 |
| 3 | 把 `k` 从 4 改成 1 和 8，观察答案变化 | `rag_core.py` | top-k 的召回 / 噪声权衡 |
| 4 | 删掉 `PROMPT` 里防幻觉那句，问一个知识库外的问题 | `rag_core.py` | 幻觉是怎么产生的 |
| 5 | 在 `tools.py` 加一个 `get_order_status(order_id)` 工具 | `tools.py` | Agent 工具的定义与注册 |
| 6 | 给 chunk metadata 加上 `page` 并透传到答案 | `loaders.py` | 检索溯源（有现成规格参考 ↓） |
| 7 | 把 `VectorStoreService` 换成 `InMemoryVectorStore` | `vector_store.py` | 面向接口编程的收益 |

> 练习 6 有一份**填好的规格**可直接对照：
> `skills/backend-sdd/examples/spec-rag-citation.md`。
> 建议先按 `skills/backend-sdd/SKILL.md` 走一遍规格流程，体会「先定义、再实现」的差别。

## 四、改代码前的规矩

涉及接口、领域逻辑、跨模块改动、数据变更、重构、疑难 Bug 时，先读
[`skills/backend-sdd/SKILL.md`](../skills/backend-sdd/SKILL.md)：
**规格 → 人工确认（硬卡点）→ 计划 → 实现 → 验证 → 回写**。

改完必须 `pytest -q` 并保留真实输出；新踩的坑回写进 `AGENTS.md` 的「已知坑点」表。
